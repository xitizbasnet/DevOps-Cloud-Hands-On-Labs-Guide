# Lab 06 — Define Variables in a Bash Script

> [!IMPORTANT]
> This lab introduces the different types of variables available in Bash, including **regular variables**, **environment variables**, **read-only variables**, **special variables**, and **default values**.

## Objective

Understand variable types: **local**, **environment**, **special**, and **read-only**.

## Prerequisites

Before you begin, ensure that you have:

* ✅ Completed **Lab 05 — Create a Simple Bash Script**.
* ✅ Access to your EC2 instance via SSH.
* ✅ A `~/scripts` directory available from the previous lab.

---

## Procedure

### Step 1 — Create the Variables Demonstration Script

Create a new script:

```bash
nano ~/scripts/variables.sh
```

Add the following content:

```bash
#!/bin/bash

set -euo pipefail

# --- Regular variables ---
APP_NAME="MyDevOpsApp"
VERSION="1.0.0"
ENV="dev"

echo "App: $APP_NAME | Version: $VERSION | Env: $ENV"

# --- Read-only variable ---
readonly MAX_RETRIES=3

echo "Max retries: $MAX_RETRIES"

# --- Environment variable export ---
export DB_HOST="localhost"

echo "DB Host (exported): $DB_HOST"

# --- Special variables ---
echo "Script name: $0"
echo "PID: $$"
echo "Last exit code: $?"

# --- Default value ---
REGION="${AWS_REGION:-ap-south-1}"

echo "AWS Region: $REGION"
```

---

### Step 2 — Make the Script Executable and Run It

Run the following command:

```bash
chmod +x ~/scripts/variables.sh && ~/scripts/variables.sh
```

Observe the output generated by the script.

---

## Understanding the Script

The script demonstrates the following Bash variable concepts:

| Variable Type            | Example                      | Purpose                                                             |
| ------------------------ | ---------------------------- | ------------------------------------------------------------------- |
| **Regular Variable**     | `APP_NAME`, `VERSION`, `ENV` | Stores values used within the script.                               |
| **Read-Only Variable**   | `readonly MAX_RETRIES=3`     | Prevents the variable from being modified after assignment.         |
| **Environment Variable** | `export DB_HOST="localhost"` | Makes the variable available to child processes.                    |
| **Special Variables**    | `$0`, `$$`, `$?`             | Provides information about the running script and execution status. |
| **Default Variable**     | `${AWS_REGION:-ap-south-1}`  | Uses a default value if the variable is not already defined.        |

## Best Practice Tips

> [!TIP]
> Adopting consistent variable naming and management practices makes Bash scripts easier to maintain and less error-prone.

### 🔤 Follow Variable Naming Conventions

Use:

* **UPPER_CASE** for global and environment variables.
* **lower_case** for local script variables.

This is the commonly accepted Bash scripting convention.

---

### 🛡️ Use Safe Default Values

Use the following pattern when referencing variables that may not be defined:

```bash
${VAR:-default}
```

Example:

```bash
REGION="${AWS_REGION:-ap-south-1}"
```

This helps avoid **unbound variable** errors when using:

```bash
set -u
```

---

### 🔐 Never Hardcode Credentials

Do **not** store credentials directly in scripts.

Instead, use:

* AWS Secrets Manager
* Environment variables supplied by your CI/CD pipeline

This improves security and simplifies credential management.

---

### 📤 Export Variables Only When Necessary

Use:

```bash
export VARIABLE_NAME=value
```

only when the variable must be available to **child processes**. Avoid exporting variables unnecessarily to keep the environment clean.
